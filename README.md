Vibe Snake is an ambitious arcade successor to Snake. **1.0 ships as a native Godot 4 .NET game with pure C# rules** (no Python runtime). A Python/Pygame checkout remains available as a frozen behavior oracle and temporary playable alpha, not as the product path. The game combines wraparound movement, starvation pressure, smooth combo scoring, tactical powers, cosmetic progression, AI spectator channels, and an eight-station in-world radio framework. The canonical repository is [blisspixel/VibeSnake](https://github.com/blisspixel/VibeSnake).

Status: Alpha 0.2.1. Hosted CI on [blisspixel/VibeSnake](https://github.com/blisspixel/VibeSnake) is green on a single `main` branch. The **product foundation** is Godot 4.7.1 + .NET 10.0.302: pure C# rules for all nine powers, platform-neutral persistence, **892** native contract tests with 90 percent line and branch floors per module, dual-runtime parity fixtures, deterministic replay recording and playback, schema-1 keyboard/controller remapping with family-aware vector prompt badges, an exact nine-case keyboard/D-pad/stick render-cadence matrix, and a keyboard/controller-complete six-section settings screen with atomic schema-7 preferences. The settings contract includes a bounded shared stick deadzone, digital D-pad fallback, Master-bus mono downmix, a functioning Vibe adaptation opt-out, and default-off local playtest consent. Product Vibe offers all nine powers under explicit protection, tempo, harvest, and geometry anti-redundancy rules; the HUD preserves the family, marker, effect, duration, and held state before collection and while active. The replay browser verifies metadata and explicit compatibility state in the background, supports 0.5x through 4x playback and HUD control, exports verified runs atomically, and requires exact two-step consent before deleting one replay. Deterministic onboarding, run-end attribution, schema-2 fair-category personal bests, a versioned native top-ten browser with explicit noncompetitive Python 0.2 import, deliberate restart, verified player-data reset and recovery, and privacy-bounded schema-2 local summary export and deletion are qualified. The deterministic balance laboratory now retains 324 paired stress runs, while a separate 2,700-run observed AI baseline is hash-locked without inventing human targets. A 120-run native league compares all ten built-in personalities over the reviewed corpus, seven behavior metric families, and 60 same-state trait interventions under noncompetitive AI score identity. A structured-human handoff, six dedicated power-synergy scenarios, and target-first balance-experiment guard keep experience verification and tuning honestly pending. Multimodal starvation, combo, power, protection, and death contracts remain attributable under minimum-effects profiles. Visual hierarchy, Vibe Level, performance, radio, broadcast, content-pack, content-curation, creator-content, artifact-signing-readiness, and native Windows, macOS, and Linux smoke gates are automated. Actual radio and broadcast audio remain unapproved. The Python alpha remains a frozen source-playable reference and oracle. Store-ready 1.0 is not ready: pack `exportEligible` is still zero, selected-store integration, actual platform signing, physical-controller and feel evidence, named-hardware performance, and structured playtesting remain. See [current status](docs/release/STATUS.md) and [roadmap](ROADMAP.md) (read **Product path** first).

Classic and Vibe are explicit `classic@1` and `vibe@1` product modes. Classic uses `classic-standard-v1`, fixed 10-point food scoring, and no starvation, combo bonuses, speed or length bonuses, near misses, powers, progression scoring, or adaptation. Vibe retains the full pressure, combo, near-miss, power, progression, and feedback model. Its deterministic `vibe-bounded-hunger-v1` policy is enabled by default, visibly reports Support, Standard, or Pressure, and changes only bounded hunger drain. Settings can disable it for unranked Vibe runs; `vibe-standard-v1-dda-on` and `vibe-standard-v1-dda-off` are never compared. The main menu and settings use the same remappable keyboard, D-pad, stick, and confirm actions.

The native shell now enters through the title menu on every profile. The tutorial is optional through Help. Start, Customize, Achievements, Local Scores, Let's Play / AI Channels, Replays, Settings, Help, and Quit are reachable by keyboard, controller, or mouse. Display settings provide classic 1024 by 768 4:3, 1280 by 720 16:9, 1440 by 900 16:10, and 1920 by 1080 16:9 window sizes plus borderless-fullscreen and exclusive-fullscreen modes. Windowed presets preserve the 1280 by 720 logical canvas without stretching; fullscreen fills the active display without applying a second aspect-ratio frame. In fullscreen the pointer hides after 1.5 seconds of inactivity, reappears on movement, and is always restored when focus leaves the game. Normal native source play also discovers the existing 95-track, eight-station checkout library; release exports continue to require approved manifest-bound packs.

The native progression foundation now exposes twenty exact mastery, discovery, and identity goals, one highlighted next goal, eight curated presentation-only cosmetic sets with five persisted loadout slots, and a twelve-event fixed-seed Broadcast Tour across four finite tiers. Keyboard and controller routes cover browsing, locked-state rejection, selection, same-seed practice, replay recording, and return. Tour practice is excluded from competitive scores and ordinary human-run metrics. Real human unlock-order, motivation, rivalry, and cosmetic review remain required before V080-04 closes.

Next milestone: **0.3.0** - close the measured Godot/C# vertical slice (packaging, pack eligibility, shell depth, evidence), not more Python features. The roadmap defines every dependent release through 1.0.0 without schedule estimates.

## Play from source

Use Python 3.11, 3.12, 3.13, or 3.14. Python 3.14 is the recommended development version. The source reference uses Pygame Community Edition so every supported interpreter has maintained native wheels on Windows, macOS, and Linux.

```powershell
git clone https://github.com/blisspixel/VibeSnake.git
cd VibeSnake
py -3.14 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --require-hashes --only-binary=:all: -r requirements-runtime.lock
python -m pip install --no-deps --no-build-isolation -e .
vibesnake
```

On macOS or Linux:

```bash
git clone https://github.com/blisspixel/VibeSnake.git
cd VibeSnake
python3.14 -m venv .venv
source .venv/bin/activate
python -m pip install --require-hashes --only-binary=:all: -r requirements-runtime.lock
python -m pip install --no-deps --no-build-isolation -e .
vibesnake
```

One-shot install scripts (clone + venv + install):

```powershell
./scripts/install_player.ps1
```

```bash
./scripts/install_player.sh
```

### Commands

| Command | Purpose |
| --- | --- |
| `vibesnake` or `vibesnake play` | Launch the game |
| `./play.ps1` / `./play.sh` / `play.bat` | Launch using the local `.venv` when present |
| `vibesnake update` | Fast-forward this checkout from GitHub `main` and reinstall |
| `vibesnake status` | Compare local commit to GitHub `main` without changing files |
| `vibesnake doctor` | Check Python, assets, and the offline radio library |
| `vibesnake version` | Print the installed package version |

```powershell
vibesnake status
vibesnake update
./play.ps1
```

`vibesnake update` pulls the latest `main` from [blisspixel/VibeSnake](https://github.com/blisspixel/VibeSnake), reinstalls the editable package, and keeps your local saves in the OS user-data directory. Use `vibesnake update --dry-run` to inspect without changing files.

**Always-current download:** every successful `main` push refreshes the floating
[player-latest](https://github.com/blisspixel/VibeSnake/releases/tag/player-latest)
release with `VibeSnake-player-source.zip`, wheels, and checksums. Tagged
releases publish the same artifacts under a version name.

## What is here

- A 64 by 33 wraparound grid rendered at 1280 by 720.
- A 30-second starvation clock and near-miss reward system.
- Smooth combo multipliers from 1x to 10x.
- Nine power-up types with tested activation, gameplay, expiry, collision, and reset behavior.
- Twenty-five persistent achievements and 10,800 cosmetic combinations.
- Ten built-in AI personalities plus loadable JSON personalities.
- Eight authored radio-station identities and a 95-track offline GTA-style radio library under `assets/audio/radio/`, released with the project as original Vibe Snake soundtrack material. A clean clone starts the full station network; procedural SFX fallbacks still cover missing event cues.
- Versioned, atomic save repositories in the operating system's user-data directory.
- Headless automated tests, an enforced 80 percent line-coverage floor, full-tree Ruff and source-policy gates, hash-locked Python dependencies, audited locked NuGet restore, local pre-commit hooks, and a GitHub Actions workflow.
- A seeded gameplay QA laboratory with property-generated input, per-step invariants, replayed trace hashes, automated policies, and JSON reports.
- A tested native foundation with PCG32 randomness, ordered events, canonical state restore, complete pure C# contracts for all nine powers, Godot full-portfolio presentation and cadence, live verified replay recording, bounded replay browsing and deterministic playback, atomic user-data storage, strict import diagnostics, generated state-machine campaigns, logical Godot input and lifecycle handling, bounded fallback-audio recovery and stress evidence, checksum-verified exports, read-only install qualification, and a reproducible artifact manifest gate.
